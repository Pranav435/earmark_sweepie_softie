# Messages that arrive while the phone is in use

Changes ADR 0017's boost and extends ADR 0019's reply strip. On the Galaxy A34, Earmark only worked for a message that arrived while the phone was locked. A message that arrived while you were using the phone got no guess, so no drift was watched, no pill came and opening its chat showed no reply strip. Then, at the next unlock, it got the "first unlock after it arrived" boost and showed up as a chip, long after its heads-up. Several of these in a row felt like a queue.

**An arrival becomes the guess, without a chip.** A Reply or Payment loop that opens or gets a new message while the phone is unlocked and in use is an arrival. Its heads-up already showed, so a chip on top would only repeat it. It quietly becomes the guess, like an unfinished flow does, so drift can bring it back. Its pill reads "Before you forget · Reply to Priya · Do it now", because you didn't come here for it. An arrival scores like a first unlock (with the boost) and still needs more than 0.70.

It only takes over a guess that is nothing yet: no guess, a finished hand-back (`Left`), or an earlier arrival whose pill hasn't shown. A guess you came for at unlock, held or faded, stays the guess. So does a pill on screen, a chat you were handed back to, or a pill you swiped away. Only a new message counts: an app posting the same message again doesn't, and nor does one more than 2 minutes old when it's posted (delivered late, or replayed when the listener reconnects).

**The boost goes to messages that came in while the phone was put down.** The engine notes when the phone is put down, meaning the screen goes off after the phone was in use. A loop updated since then gets the +0.15 boost at the next unlock, however long after. One that came in while you were using the phone doesn't, because you saw its heads-up. A screen that only lit up on the lock screen for a notification doesn't count as putting the phone down. Before the engine has seen the phone put down, every loop gets the boost, as before.

The phone is in use from an unlock, or from anything the foreground poll reports, until the screen goes off. The poll only runs while the phone is unlocked. Its ticks count too, because after an update the listener reconnects mid-session with no unlock and maybe no app switch. The poll's first query now looks back an hour instead of 10 seconds, so it reports the app already in front, and a feed you were in when the listener reconnected counts for drift.

**A tap on any message's notification opens its chat with the reply strip.** ADR 0019 kept the strip for the guessed loop only. A tap names the chat, so a tap on any Reply loop with a reply action now opens that chat. Earlier, tapping a message that wasn't the guess closed its loop as done, with no strip. An app clearing a notification still opens the chat only for the guess, because WhatsApp clears every notification when it opens to the chat list.

The tapped chat becomes the guess for a detour. When it closes (you reply, leave the app or turn the screen off), the guess it took over comes back with a fresh drift timer. Its dot stays meanwhile, and a pill it already showed doesn't show again. If the guess was itself an open chat, moving to another chat closes it as done.

**Consequences:** most direct messages that arrive during use get a pill if you drift. The three-ignores mute and the one-pill-per-message limit (ADR 0021) still apply. Smart Reply still decides whether the strip has anything in it: on the emulator it answered 8 of 11 test messages, and said "not English" for a Hinglish message and for "ok" and "lol", which are too short for its language check. The Log screen now gives that reason in words.
